### Codex limitation

The App Server process that created the target did not deliver a terminal notification during
the observation window even though the persisted target reached `task_complete`. The private
probe was stopped after that persisted completion became visible, and a fresh App Server
process read the completed target immediately. This live observation supports reconciliation
by authoritative `thread/read`, but it does not prove a notification-only production
controller. No Codex hook lifecycle event was required or observed.

Recommended direction: operator-visible rollover with controller-managed App Server thread
creation and mandatory readback reconciliation. Do not ship a notification-only controller
from this single run.

### Claude disposition

The Claude threshold, message projection, safe stop, handoff, fresh UUID session, bootstrap,
target readback, one-shot consumption, retry after a real target failure, and multi-chat
collision behavior remain unobserved live. Simulated CR-03/CR-06 evidence is not substituted
for those missing observations.

Recommended direction: visible `no-go`. Do not test or restore `--autocompact`; do not start a
150,000-token fixture until a zero-token minimal `claude -p` transport probe succeeds. A future
Claude live retry must remain separately authorized and cannot borrow Codex evidence.

## Claim boundary

- The Codex run proves one authenticated source observation and one fresh-thread restoration;
  it does not prove unattended production reliability, hook-only rollover, or every retry
  edge.
- The Claude run proves only startup-hook identity and a fail-closed transport no-go.
- Neither result installs a controller, hook, service, scheduled task, or global setting.
- No production follow-up is silently authorized. A controller implementation must first be
  recorded through a focused spec and new tracer-bullet tickets.
