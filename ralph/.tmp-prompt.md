feat(deepeval): add EvalController JWT auth and integration tests

Implements issue 02 from deepeval-python-runner change.

Key decisions:
- EvalController switched from X-Api-Key to JWT [Authorize] so the
  DeepEval runner and Confident AI harness both authenticate via
  standard Bearer tokens. ConfidentAiOptions.EvalApiKey is no longer
  read by the controller.
- ControllerBase is kept intentionally (not BaseController): the
  response must be a plain JSON object without the Skeleton envelope
  so Confident AI's output key path ["output"] resolves at the root.
- New test project Api.IntegrationTests.xUnit uses a manual
  WebApplication.CreateBuilder() factory (per CLAUDE.md findings:
  standard WebApplicationFactory does not work with Skeleton v8).
- Real JWT generated with the Localhost JwtSecret (symmetric HMAC256)
  so the same token validation parameters are used in production.
- TestFluentValidationFilter is an inline action filter that mirrors
  the Skeleton's ValidationModelStateFilter (which is not resolvable
  from external test assemblies): runs IValidator<T>, returns 422
  with AIA error codes when validation fails.
- Asp.Versioning AddApiVersioning() registered in the test server to
  resolve the apiVersion route constraint.
- Errors.json loaded from Errors/ output directory (copied there by
  Common.csproj build task, same path used by Application.UnitTests).
- Fixed 2 pre-existing test assertions in EvalChatServiceTests:
  captured.InteractionHistory is the live collection; after ExecuteAsync
  the service appends the assistant interaction, so expected count is
  +1 vs the comment ("2 seeded + 1 user" → 4; empty history → 2).

feat(deepeval): extend EvalChat for DeepEval scenario mode

Implements issue 01 from deepeval-python-runner change.

Key decisions:
- EvalChatRequest gains Message (string?), Customer (EvalCustomerDto?), and
  History (List<EvalTurnDto>?) for the DeepEval stateless scenario mode.
  When Message is non-null, the service routes to ExecuteScenarioAsync;
  otherwise the existing Confident AI multi-turn path (Input/State) is used.
- EvalChatResponse gains ActualOutput (mirrors Output) and ToolsCalled
  (List<EvalToolCallDto> with name/input/output) extracted from the
  interactions added by the gateway AFTER the seeded history.
- EvalChatService.BuildScenarioConversation materialises Person/Customer
  in memory from EvalCustomerDto (identified) or returns a plain Person
  (unidentified), mirroring EvalRunner.Core.Dataset.PersonBuilder logic.
- History turns (user/assistant/tool_call/tool_result) are replayed via
  MapTurn into InteractionHistory before the agent call, matching the
  HistoryReplayer pattern from tools/dotnet/EvalRunner.
- No MongoDB calls in scenario mode: CreateAsync/UpdateAsync are never
  invoked, so the endpoint is fully stateless for the DeepEval runner.
- EvalChatRequestValidator updated: When x.Message != null (scenario mode)
  validates Message; otherwise (Confident AI mode) validates Input.
  All existing validator tests pass unchanged.
- 6 new unit tests cover: identified customer, unidentified person,
  empty history, seeded history ordering, tools_called extraction
  (only from this turn, not from seed), and gateway error propagation.

## What to build

Crear el runner de evaluación Python en `tools/python/evalrunner/` usando DeepEval y el SDK de Confident AI como estándar. El runner descarga los goldens del dataset `chat-gold` desde Confident AI, llama al endpoint `POST /api/v1/eval/chat` por cada golden para obtener `actual_output` y `tools_called`, construye un `LLMTestCase` por golden, y ejecuta las 5 métricas nativas de DeepEval. Los resultados se sincronizan automáticamente a Confident AI al ejecutar `deepeval test run`.

El LLM judge se configura con el mismo deployment de Azure OpenAI que usa el agente. Toda la configuración se lee desde variables de entorno.

## Acceptance criteria

- [ ] `tools/python/evalrunner/` contiene: `test_agent.py`, `conftest.py`, `requirements.txt`, `.env.example`, `README.md`
- [ ] `EvaluationDataset.pull(alias="chat-gold")` carga los goldens correctamente
- [ ] Por cada golden, el runner llama `POST /api/v1/eval/chat` con el escenario del `additional_metadata` y construye `LLMTestCase(input, actual_output, expected_output, tools_called)`
- [ ] Si la llamada HTTP falla para un golden, ese test case se marca como fallido y el run continúa
- [ ] Las 5 métricas están configuradas: `GEval` (Correctness), `HallucinationMetric`, `FaithfulnessMetric`, `AnswerRelevancyMetric`, `ToxicityMetric`
- [ ] El judge LLM es `AzureOpenAI` configurado con `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT`
- [ ] `deepeval test run tools/python/evalrunner/test_agent.py` completa y los resultados aparecen en el dashboard de Confident AI
- [ ] Variables de entorno requeridas documentadas en `.env.example`: `EVAL_API_URL`, `EVAL_JWT_TOKEN`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT`, `CONFIDENT_API_KEY`
- [ ] `README.md` documenta: requisitos (Python 3.11+), instalación (`pip install -r requirements.txt`), configuración del `.env`, y comando de ejecución
